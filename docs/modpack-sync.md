# 콘텐츠 제작팀 모드팩 동기화

MC DevKit 1.9.0에서는 호스트가 승인한 배포를 참가자의 **게임 시작** 버튼에서 적용합니다. 호스트와 참가자 모두 1.9.0 이상을 사용하세요.

1.9.1부터 앱 시작 시와 15분마다 자동 업데이트를 확인합니다. 다운로드가 끝난 뒤 서버·게임·빌드·촬영 모드·터널 작업이 끝나고 앱이 트레이에 있으면 설치 후 재실행합니다. 이전 버전에서는 한 번 완전 종료하거나 업데이트 재시작을 선택해 1.9.1을 설치하세요.

## 서버 종류

기존 Paper / Fabric / Vanilla / Arclight / Cardboard를 모두 유지하며 독립 Forge / NeoForge를 추가했습니다. 설정에서 종류별 공식 Minecraft 버전과 서버 로더 버전을 선택할 수 있습니다. 촬영용은 정확한 로더 버전을 고정하세요. Forge는 권장 버전을 우선하고 NeoForge는 베타를 제외한 최신 안정 버전을 사용합니다. 직접 선택하면 해당 버전으로 고정합니다.

공식 Maven 설치 파일의 SHA-1을 검증하고 설치 성공 후 실행 파일을 반영합니다. 업데이트 전 실행 파일은 서버 프로필의 `runtime-backups`에 보관합니다. 월드·모드는 설치 대상에서 제외합니다. 제작 프로젝트의 Fabric / Forge / NeoForge 메타데이터를 인식해 빌드 산출물을 해당 서버의 `mods`에 연결합니다.

## 호스트

1. 서버·게임 버전별 프로필을 만들고 **모드팩** 탭에서 참가자 로더를 설정합니다.
2. `client-mods`에는 제작 모드와 참가자에게 필요한 의존 모드만 넣으세요. 서버 mods를 원본으로 쓰려면 파일 규칙으로 공용 모드를 선택하세요. 예: `creator-*.jar, fabric-api-*.jar`.
3. 공용 설정 폴더와 공유 파일 규칙을 선택합니다. 예: `creator.toml, creator/*.json`. 비워두면 설정을 공유하지 않습니다.
4. **검사 · 배포 준비**를 누르고 추가·교체·제거와 검사 결과를 확인한 뒤 **변경분 승인**을 누르세요. 오류는 승인을 막고 빈 배포는 별도 옵션을 선택해야 합니다.
5. 폴더 변경 자동 감지는 변경분을 준비합니다. 기본 승인 모드에서는 승인할 때까지 현재 배포를 유지합니다. 검사 통과 시 자동 배포도 선택할 수 있습니다.
6. **촬영 모드**는 현재 승인 배포를 고정합니다. 원본이 바뀌어도 변경분만 준비하며 앱 재시작 후에도 고정을 유지합니다. 촬영 모드를 해제한 뒤 변경분을 승인하세요.
7. 관리 서버 공유 터널을 켜고 참가 링크를 전달하세요. Minecraft 접속용 playit 주소와는 별도입니다.

참가자 준비 현황은 참가 앱의 상태 보고이며 Minecraft 접속 여부와는 다릅니다. 최근 60초 내 보고가 있고 승인 배포와 적용 배포가 같아야 준비 완료입니다. 참가자 PC 경로나 계정 정보는 보내지 않습니다. 이전 승인 배포 기록에서 **복원 배포**를 누르면 참가자의 다음 게임 시작에 복원 배포가 적용됩니다. 복원 후 배포 정책은 승인 모드입니다.

## 참가자

1. 서버와 같은 Minecraft·로더를 설치하고 서버별 별도 게임 인스턴스를 만드세요. 공식 런처는 설치 설정의 게임 디렉터리로 분리할 수 있습니다.
2. 홈의 **서버 참가**에서 링크와 런처·검색된 게임 프로필을 선택하세요. 기본 위치 밖의 프로필은 게임 폴더 직접 선택으로 `mods`의 상위 폴더를 연결합니다.
3. 호스트에게 표시할 이름과 공용 설정 적용 여부를 선택하세요. 환경을 자동 판정할 수 없는 폴더는 실제 버전·로더를 확인하고 직접 확인 옵션을 선택해야 합니다. 판정된 환경의 불일치는 이 옵션으로 우회할 수 없습니다.
4. 참가 서버의 **게임 시작 · 자동 적용**을 누르면 승인 배포를 다운로드·검증·백업·적용합니다. 적용 중 호스트 배포가 바뀌면 최신 배포를 다시 확인합니다.
5. 적용 성공 후 열린 런처에서 연결한 프로필의 플레이를 누릅니다. 로그인과 게임 실행은 해당 런처가 담당합니다. 실행 파일이 검색되지 않으면 한 번 선택하세요. **런처 · 바로가기 연결**에서 해당 게임 프로필의 `.lnk`도 연결할 수 있습니다.

앱은 15초마다 배포·연결 상태를 확인합니다. 확인만으로 게임 파일을 바꾸지 않습니다. **미리 적용**으로 다운로드를 먼저 마칠 수도 있습니다. 업데이트 확인을 중지해도 게임 시작은 최신 배포를 확인합니다. 공용 설정이 배포에 포함됐는데 설정 적용을 끈 경우 시작을 중단하고 안내합니다. 게임 실행 중에는 적용과 시작을 보류합니다.

## 파일 보호와 복원

- 모든 다운로드의 SHA-256·크기를 확인한 뒤 파일을 교체합니다. 다운로드 실패는 현재 파일을 바꾸지 않습니다. 교체 중 실패는 롤백하며 중단 기록이 있으면 다음 적용 전에 복구합니다.
- 개인 모드 이름 충돌·관리 모드의 사용자 수정을 발견하면 중지합니다. 개인 파일을 옮기거나 새 인스턴스를 선택하세요.
- 공용 설정은 동의를 선택한 파일만 덮어쓰고 기존 파일을 백업합니다. options.txt·키 설정·계정·토큰 관련 파일은 배포하지 않습니다.
- 백업은 `mods/.mc-devkit-backups/<작업 ID>/mods/`와 `config/`에 남습니다. 수동 복원은 게임을 종료하고 해당 폴더들을 게임 루트의 같은 폴더로 복사하세요. previous-manifest.json을 mods/.mc-devkit-sync.json으로 복원해야 관리 상태도 일치합니다. 이전 manifest가 null이면 상태 파일을 제거하세요. 기존 1.8 백업은 작업 폴더 바로 아래에 모드가 있습니다.
- 참가 해제는 연결만 없애며 설치 파일과 백업은 남습니다.

검사는 모드 메타데이터를 기준으로 게임·로더·필수 의존성·중복 ID·충돌을 판정합니다. 모든 실행 오류를 판정할 수는 없으므로 촬영 전에 실제 게임에서 확인하세요. 다른 Minecraft 버전용으로 모드를 자동 변환하지 않습니다. 게임·로더가 바뀌면 서버와 참가 인스턴스를 분리하세요.

## 초대와 고정 주소

초대 재발급·중지는 기존 참가 연결도 만료시킵니다. 재발급 링크로 같은 게임 폴더에 다시 참가하면 연결을 갱신합니다. 호스트 앱과 공유 연결이 실행 중이어야 받을 수 있습니다.

임시 Cloudflare 주소는 터널 재시작 시 바뀝니다. **고정 Cloudflare 터널**을 사용하려면 호스트 계정에서 도메인과 터널을 만들고 공개 호스트 서비스 URL을 `http://localhost:3847`로 설정하세요. DevKit에는 고정 HTTPS 주소와 터널 토큰을 저장합니다. 토큰은 PC에 보관하며 API 응답과 명령행 인수에는 표시하지 않습니다. [Cloudflare 공식 구성 안내](https://developers.cloudflare.com/tunnel/configuration/), [터널 토큰](https://developers.cloudflare.com/tunnel/reference/tunnel-tokens/).

기존 프록시가 있으면 **기존 고정 주소 · 외부 프록시**를 선택할 수 있습니다. 도메인·계정·외부 프록시 자체를 자동 생성하지는 않습니다.

## 검증

`npm test`는 배포 승인·촬영 고정·복원, 모드·설정 적용, 충돌 보호, 실패·중단 복구, 초대·준비 보고, 프로필 판정과 Forge·NeoForge 설치를 검사합니다. `scripts/check-versions.js`는 일곱 종류의 공식 버전 목록을 확인합니다.

`scripts/forge-smoke.js`는 격리된 .test-data/forge-smoke에서 공식 Forge·NeoForge 1.21.1을 설치하고 루프백 테스트 포트로 시작·종료합니다. `scripts/ui-smoke.js`는 별도 Electron 데이터에서 설정·승인 배포·촬영 모드·참가 UI를 확인합니다. 실제 사용자 서버는 사용하지 않습니다.
