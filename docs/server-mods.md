# 방송 서버의 모드 관리와 공유

MC DevKit의 중심은 서버 관리입니다. 서버 프로필의 **모드팩** 탭에서 방장이 모드를 찾고 서버 환경을 구성한 다음, 승인한 모드와 공용 설정을 참가자에게 공유합니다. 계정 연결과 직접 게임 실행은 참가자를 위한 보조 기능입니다.

## 방장: 검색에서 공유까지

1. Fabric·Forge·NeoForge 서버 프로필에서 Minecraft 버전과 로더를 설정합니다. 모드팩 탭의 저장된 배포 환경이 검색 기준입니다. 서버 모드는 서버를 중지한 뒤 변경합니다.
2. **모드 검색 · 설치**에서 이름을 검색합니다. 현재 검색 공급자는 **Modrinth**이며 CurseForge 카탈로그/API는 연결하지 않습니다.
3. **버전 선택**에서 정확한 호환 버전을 고릅니다. **서버 + 참가자**, **참가자만**, **서버만** 중 지원되는 위치에 설치합니다. 예를 들어 렌더링 모드는 참가자만, 서버 전용 최적화 모드는 서버만 선택합니다.
4. 선택한 모드의 필수 의존 모드를 재귀적으로 찾습니다. 필요한 버전이 없거나 서로 다른 모드의 고정 버전 요구가 충돌하면 설치를 중단합니다. 선택 의존 모드는 자동으로 추가하지 않습니다.
5. 서버 모드는 해당 서버의 `mods`, 참가자용 모드는 배포 원본인 `client-mods` 또는 사용자가 지정한 폴더에 들어갑니다. 참가자 파일이 기존 배포 규칙에 포함되지 않으면 해당 파일 규칙을 추가합니다. 카탈로그에서 설치한 파일과 버전을 서버 채널별로 기록합니다.
6. 공용 `config` 폴더와 공유 파일 규칙을 고릅니다. 예: `creator.toml, creator/*.json`. 비밀번호·계정·토큰·개인 키 설정은 공유하지 않습니다.
7. 준비된 변경분과 검사 결과를 보고 **변경분 승인 · 참가자에게 배포**를 누릅니다. **참가 링크 복사**로 링크를 전달합니다. 기본 정책은 검사 후 승인이고, 검사 통과 시 자동 배포도 선택할 수 있습니다.

모드 검색 화면에서 설치할 때는 저장된 배포 설정을 사용합니다. 원본 경로, 로더 또는 공용 설정 규칙을 화면에서 수정했다면 먼저 **검사 · 배포 준비**로 저장하세요. 참가자는 같은 Minecraft·로더의 별도 게임 폴더를 연결하고 공용 설정 적용을 켭니다.

## 모드 새 버전 자동 업데이트

카탈로그로 설치한 모드는 앱 시작 약 30초 후와 이후 **30분마다** 새 안정 버전을 확인합니다. 서버 채널 전체 자동 확인과 개별 모드의 자동 확인을 끌 수 있습니다. 버튼으로 즉시 업데이트를 확인할 수도 있습니다. 별도로 넣은 개인 JAR의 출처나 업데이트를 추측하지 않습니다.

- 서버의 Minecraft 버전과 로더를 유지하고, 같은 환경용 정식 릴리스만 자동 선택합니다. Minecraft·로더 자체를 자동으로 올리지 않습니다. 직접 설치한 베타보다 오래된 안정 버전으로 되돌리지 않습니다.
- 필수 모드의 고정 버전과 필요한 의존성을 함께 확인합니다. 변경 없는 파일은 로컬 해시를 검증해 재사용합니다.
- 서버가 실행·시작·중지 중이면 서버 파일 변경을 보류합니다. 서버를 임의로 재시작하지 않습니다. 중지 후 다음 자동 확인을 기다리거나 업데이트 버튼을 누릅니다. 파일 적용 중에는 서버 시작을 차단합니다.
- **촬영 모드**에서는 카탈로그 설치와 업데이트를 보류하고 승인된 배포를 유지합니다. 촬영 종료 후 다시 확인합니다.
- 기본 승인 정책에서는 새 모드를 받은 뒤 변경분을 준비하고 방장의 승인을 기다립니다. **검사 통과 시 자동 배포** 정책에서는 검사에 통과한 배포가 자동으로 공유됩니다.
- 참가자 앱은 최신 승인 배포를 확인하고 **다음 게임 시작 전**에 다운로드·백업·적용합니다. 실행 중인 게임 파일은 교체하지 않습니다. 따라서 방송 도중 모든 참가자의 버전이 갑자기 바뀌지 않습니다.

API의 버전·로더 정보와 모드 메타데이터 검사가 실제 실행 호환성을 모두 보장하지는 않습니다. 방송 전에 서버와 참가자 게임을 실행해 확인하고 촬영 모드로 고정하세요.

## 다운로드와 기존 파일 보호

Modrinth의 공식 CDN 주소만 다운로드하며 크기와 공개 SHA-512(또는 SHA-1) 해시를 확인합니다. 모든 필수 파일을 받은 후 교체합니다. 직접 수정한 관리 모드나 같은 이름의 다른 파일은 덮어쓰지 않습니다. 교체 실패 시 기존 파일을 복구하며, 복구하지 못하면 백업 위치를 안내합니다. 공용 설정과 월드는 카탈로그 업데이트 대상에 포함하지 않습니다.

방장의 파일 기록은 서버 채널의 `catalog-installed.json`에 저장합니다. 참가자의 적용 백업 및 배포 복원은 [모드팩 동기화](modpack-sync.md)의 기존 절차를 따릅니다.

## 계정과 직접 실행

참가자는 [Microsoft 계정 연결](minecraft-account.md)을 사용해 기존에 설치한 게임 프로필을 바로 실행할 수 있습니다. 앱 배포자의 Client ID와 Minecraft API 승인이 필요하며 이 저장소에는 다른 런처의 ID나 토큰을 넣지 않습니다. 게임·로더·리소스를 처음 설치하는 작업은 연결한 런처에서 수행합니다. 직접 실행을 지원하지 않는 캐시 형식은 외부 런처 실행을 사용합니다.
